# 操作系统题库 OCR 双库识别质量审计报告

## 1. 审计对象

| 标识 | 文件                                                  |
| ---- | ----------------------------------------------------- |
| db1  | `db1_parsed.csv`，来源于 `postgraduate_repaired_1.db` |
| db2  | `db2_parsed.csv`，来源于 `postgraduate_repaired_2.db` |

审计字段：

- `question_imports.parsed_content`
- `question_imports.parsed_options`

两份文件均读取到 568 条数据记录，ID 范围最高到 582，中间存在部分缺号。

## 2. 审计口径

本报告从操作系统学科审题人的角度进行判断，而不是单纯比较字符串是否完全相等。

以下差异不直接作为 OCR 准确率下降处理：

- JSON 空格、缩进和键顺序不同；
- 中文直接编码与 `\uXXXX` 转义不同；
- 全角、半角标点差异；
- 不影响题意的换行差异；
- `segments` 中相同文本采用不同序列化方式。

以下情况被认定为有效识别差异：

1. 题干缺字、截断或串入无关内容；
2. 罗马数字、变量、上下标和数学表达式识别错误；
3. 表格、代码或页面访问序列缺失；
4. 选项内容改变、选项串题或选项重复；
5. 差异导致题目无法作答、正确答案发生变化或无正确选项；
6. 原页题号残留、广告水印等不应进入生产题库的内容。

## 3. 总体结论

### 3.1 OCR 文字恢复能力

**db2 的题干恢复能力整体高于 db1。**

db2 在含有以下内容的题目中表现明显更好：

- 表格；
- 并发程序代码；
- 页面访问序列；
- 调度参数表；
- 进程编号和变量下标；
- 被图像区域分割的长题干。

例如，db1 在 ID 151 和 155 中只保留了严重错乱的表头和进程名，而 db2 重建出了各进程的 CPU/I/O 比例、等待时间、运行时间和优先权数据。

### 3.2 选项忠实度与污染风险

**db1 的 `parsed_options` 整体比 db2 更稳。**

db2 存在多次“修复过度”或跨题污染：

- 将上一题或相邻题目的选项复制到当前题；
- 为了补全文本而修改原题选项；
- 删除原题判断条件；
- 把无关短语放入选项；
- 将正确的指数、编号或符号改成普通数字。

例如：

- ID 283 中，db1 保留了完整的内部碎片题目及选项；db2 的题干只剩一项，选项则被替换成上一道段页式管理题的内容。
- ID 375 中，db1 保留了“提前读、连续簇、延迟写、磁盘高速缓存”的完整选项，db2 的大部分选项被上一题的权限位数选项污染。
- ID 415 中，db1 的 DMA 操作顺序和四个箭头选项完整，db2 的 C、D 选项出现 `@` 字符并丢失步骤编号。

### 3.3 生产选型结论

若必须整库二选一：

> **建议以 db1 作为生产基线，但不能未经修复直接上线。**

原因是题库生产风险应优先考虑：

1. 选项是否忠于原题；
2. 是否仍存在唯一且合理的正确答案；
3. 是否会发生串题；
4. 是否会错误影响判分。

题干缺失通常可以通过下架题目或回源修复发现；错误选项和串题则更容易在表面可读的情况下进入线上判分流程，风险更隐蔽。

最优生产方案不是直接选择一份数据库，而是：

> **以 db1 的 `parsed_options` 为主，以 db2 的复杂题干恢复结果为补充，按照本报告中的 ID 白名单进行字段级合并。**

## 7. 低风险差异

### 7.1 原页题号残留

db2 在大量记录中保留了诸如：

- `13.`
- `30.`
- `44.`
- `31.【2012统考真题】`

等原页题号。

该问题在后半部分数据中尤为集中，特别是 ID 443～575 附近。题号残留通常不改变题意，但会造成：

- 前端显示重复题号；
- 题库搜索文本不干净；
- 相似题去重受到干扰；
- 训练数据带入无意义序号。

建议在入库前只对题干开头执行规则化清理，不要删除正文中的步骤编号、罗马数字和年份。

建议规则：

```regex
^\s*\d{1,3}[.、]\s*
```

需排除以年份、公式或程序行号开头的特殊题目。

### 7.2 标点和空格差异

以下类型通常不影响题意，可通过统一格式化解决：

- `()` 与 `（）。`
- `I/O` 与 `IO`
- `P,V` 与 `P，V`
- `T1+T2+T3` 中的空格；
- 中文逗号、英文逗号；
- `μs` 与 `us`；
- 选项末尾多余句点。

但下列情况不能按普通格式差异处理：

- `R0` 与 `RO`；
- `I/O` 与 `I1O`；
- `2^32` 与 `232`；
- `P2` 与 `P^{2}` 在非渲染环境下的差异；
- `I、III、IV` 与 `I、II、IV`。

## 9. 上线前自动检查规则

### 9.1 选项结构检查

每条选择题至少应满足：

- 选项键为连续的 A、B、C、D，或明确允许 A～E；
- 不允许两个选项文本完全相同；
- 不允许某个选项包含完整的另一道题题干；
- 不允许选项出现公众号、网址、二维码说明等水印文本；
- 不允许某选项与前一 ID 的选项高度相似而与当前题干无关。

### 9.2 组合题检查

题干出现 I、II、III 等编号时，应检查：

- 编号是否连续；
- 是否出现重复编号；
- 选项引用的编号是否都存在；
- 题干只有 I、II、III 时，选项不能引用 IV；
- 罗马数字 `II` 不得被识别为 `I1`、`11` 或字母组合。

### 9.3 表格和代码题检查

题干包含以下表达时应自动进入复杂题检查：

```text
如下表
见下表
如下图
代码如下
程序如下
页表
段表
资源分配
到达时间
运行时间
页面访问序列
```

检查要求：

- 有图像资源但无文字表格时，标记为依赖图片；
- 文本声称“如下表”但没有表格、图片或结构化数据时，不得发布；
- 代码题必须至少包含变量初值和关键指令；
- 计算题中的时间、容量、页号和资源数不得为空。

### 9.4 数学与符号检查

重点检测以下高频 OCR 错误：

| 错误形式  | 正确形式示例                      |
| --------- | --------------------------------- |
| `RO`      | `R0`                              |
| `I1O`     | `I/O`                             |
| `216`     | `2^16`                            |
| `232B`    | `2^32 B`                          |
| `P^{2}`   | 按展示规范转成 `P2` 或保留 LaTeX  |
| `T^{3}`   | 根据原题判断是 T3 还是 T 的三次方 |
| `[phone]` | 回源识别，不得直接保留            |

## 10. 最终评级

| 文件                       | 审计评级     | 说明                                               |
| -------------------------- | ------------ | -------------------------------------------------- |
| db1                        | C+           | 选项相对可靠，普通题较稳，但复杂题题干缺失较多     |
| db2                        | C            | 复杂题恢复明显更好，但串题和选项污染使判分风险偏高 |
| 字段级合并并完成人工回源后 | 可达到 B+/A- | 仍需自动规则和抽样审题                             |

## 11. 最终决策

1. **不要将 db2 整库覆盖 db1。**
2. **以 db1 作为生产底库。**
3. **对本报告列出的 db2 优胜 ID 进行白名单式覆盖。**
4. **选项字段原则上以 db1 为准，除非已经由审题人确认。**
5. **共同缺陷 ID 必须回到原始扫描页人工校对。**
6. **合并后重新进行组合题、表格题、代码题和公式题专项检查。**

最终判断：

> db2 的 OCR 题干识别精度更高；db1 的整库生产安全性更高。
> 从题库生产使用角度，推荐“db1 为底库、db2 定点修复”，而不是选择 db2 直接上线。
