# 项目规则 (长期稳定)

> 2240AI — 考研智能刷题小程序（数学二 / 408 / 英语）
>
> 更新时间：2026-11-02
> 2026-11-02 变更原因：项目已上线并进入稳定性治理阶段，将开发期“先实现、后优化”口径调整为生产期稳定优先；业务边界、安全要求与质量门禁不变。

---

## 明确不做什么

- ❌ OCR 识别手写题；OCR 导题流水线本身已实现，但不承诺手写识别
- ❌ LangChain / Agent / 多模型编排
- ❌ 脱离现有数据域的复杂知识图谱/推荐算法；当前知识图谱与推荐实验能力必须复用既有模型和权限边界
- ❌ 微服务 / Kubernetes
- ❌ 社区 / 论坛 / 排行榜
- ❌ 实时协同（多人编辑/同步状态）；既有导出进度等单向 WebSocket 推送属于已实现例外
- ❌ 账号密码登录 / 邮箱注册 / 密码重置
- ❌ 多方式登录体系（仅微信 openid）
- ❌ 在线公式编辑器（LaTeX 手动输入）

---

## 核心约束

1. **无传统账号系统** — 微信 openid 是 App 用户唯一标识；Admin 后台如需权限体系，必须限定在后台管理域内，不改变 App 登录模型
2. **无纯 AI 自动入库** — 所有导入必须经过 `question_imports` + 人工确认
3. **Excel 导题优先** — 能走 Excel 就不要写解析代码
4. **SM-2 调度使用 ReviewSchedule 表** — WrongQuestion 仅保存错题分析与状态，不冗余保存复习参数
5. **后端不管理 App 用户密码** — App 身份验证依赖微信
6. **AI 是辅助** — 不影响核心刷题流程

> 2026-05-31 更新原因：对齐 `CLAUDE.md` 与已存在 Admin 文档分区，明确“不做权限体系”仅指 App 多租户/社区类权限，不否定 Admin 后台 RBAC 文档。

## 开发阶段定位（2026-11-02）

- 项目已上线运行，技术决策以长期稳定性、可靠性、可维护性、可扩展性和生产安全为优先；交付标准是行为兼容、验证通过、可观测且可回退，不以“功能能运行”作为主要标准。
- 保持高内聚、低耦合、模块职责清晰和依赖方向明确；在稳定边界上做合理抽象，避免过度设计，也避免以“先跑通”为由积累新的结构债务。
- 技术债务必须显式登记、评估影响并按批次治理；既有超限模块不因行数自动拆分，结构改动须有真实消费者、缺陷或可测试性问题作为依据。
- 生产部署、迁移、重启和用户数据操作继续遵循独立授权、备份和验收要求，不因开发阶段变化而放宽。

## 导入管线架构原则

1. **OCR 与 AI 解耦** — OCR 只负责文本提取，AI 只负责修复/补全，不互相依赖
2. **Prompt 禁止硬编码** — 运行时 AI Prompt 模板集中在 `backend/app/ai/prompts*.py` 并维护版本；Agent/开发 Prompt 在 `/prompts`；禁止把业务 Prompt 散落在无关模块
3. **AI 仅用于修复/补全/结构化增强** — 禁止将所有内容直接丢给 LLM，优先规则解析
4. **优先规则解析** — 规则能解决的问题不用 AI，AI 仅处理规则无法覆盖的边界情况
5. **核心逻辑必须支持单元测试** — AI 调用可 mock，规则逻辑必须可测
6. **分批治理，每批可运行/可测试/可回退** — 大规模重构按有限账本分批推进，保持行为与接口兼容，不一次性改动整个系统

## 开发规范

### Python

- Python 3.11+，类型注解全覆盖
- 使用 `ruff` lint + format
- 抽象按需引入：不为形式添加无消费者的抽象层或接口；确需抽象时先有复用/测试证据，并用兼容测试锁定行为。不用 `__init__.py` 做重导出
- 新增或拆出的业务模块遵循 **300 行 / 50 行** 预算；既有超限模块按重构账本处置，不因行数自动拆分

### API

- Base URL: `/api/v1`
- 响应模型沿用各领域既有 Pydantic schema；错误使用现有 HTTP 错误契约，不新增或绕过统一错误处理
- 分页沿用 `PaginatedResponse`：`{items, total, page, page_size, total_pages}`；不新增 camelCase 变体
- 路由只做参数校验，业务下沉到 services/

### 数据库

- 索引以真实查询和执行计划为依据：新增高频查询先评估索引，不凭猜测堆索引，也不让生产慢查询长期存在
- 迁移以前向演进和审计为主；生产执行前先备份，恢复/回退走已验证的备份与演练流程，不承诺未演练的自动回滚
- 复杂查询先核对执行计划与数据量，避免无界 N+1 和过深 join；既有兼容行为保持不变

### AI

- 不引入 langchain / llamaindex
- 直接 httpx 调 OpenAI-compatible 网关（Qwen/GLM 等，模型由 Admin API 配置于数据库）
- 失败降级优先于重试
- 运行时 Prompt 沿用 `backend/app/ai/prompts*.py` 并维护版本；Agent/开发 Prompt 在 `/prompts`。AI 模型凭据经 `admin_ai_model_configs` 由 Admin API 管理，不写环境变量
