# 学习统计页 UI 优化规划文档

## 一、任务背景

根据 `prompts/tasks/current-task.md`，本次任务聚焦于 **微信小程序学习统计页面** 的 UI 优化与数据可视化能力提升。

当前目标不是单纯美化页面，而是让学习统计页更符合 2240AI 的产品定位：

- 简洁
- 专业
- 现代
- 专注学习
- 不过度花哨
- 更有数据分析价值
- 更贴近学习产品，而不是 AI 大屏或营销页风格

参考风格包括：

- 网易有道
- 不背单词
- Anki
- OpenAI
- Notion

本次优化对象主要是：

```text
miniprogram/pages/dashboard/dashboard.wxml
miniprogram/pages/dashboard/dashboard.wxss
miniprogram/pages/dashboard/dashboard.js
```

---

## 二、核心目标

### 1. 提升学习统计页整体美观度

通过统一卡片、间距、圆角、阴影、色彩和信息层级，让页面看起来更成熟、更像专业学习产品。

### 2. 提升数据可视化能力

根据数据类型合理选择图表，而不是简单堆叠数字卡片。

重点图表类型包括：

- 折线图：学习趋势、刷题趋势、正确率趋势
- 柱形图：各学科做题数量对比
- 饼图 / 环形图：学科占比、题型占比
- 进度环：学习进度、目标完成度、总正确率

### 3. 增强学习产品氛围

页面应体现“学习复盘”“数据反馈”“下一步行动建议”的感觉，而不是 AI 炫技、数据大屏或过度装饰。

### 4. 保持微信小程序原生兼容

不新增依赖，不引入外部图表库，优先使用：

- WXML
- WXSS
- 原生 Canvas
- 轻量 JS 数据预处理

## 三、当前页面存在的问题

### 1. 页面视觉风格仍有不稳定感

当前 Dashboard 已经具备一定图表结构，但部分区域仍可能存在以下问题：

- 顶部 Hero 与页面整体暖白学习感容易割裂。
- 如果使用深色、强渐变、英文 AI 文案，会显得“AI 味”过重。
- 学习统计页应更接近学习复盘工具，而不是智能大屏。

影响：

- 降低产品一致性。
- 用户会感觉页面像临时拼出来的 AI 展示页。
- 与首页、错题本等学习型页面气质不统一。

### 2. KPI 信息容易堆叠

学习统计页包含较多数据：

- 累计刷题
- 学习时长
- 连续天数
- 今日刷题
- 今日正确
- 今日用时
- 待复习
- 总正确率
- 学科分布
- 行为分析
- 复习风险

如果全部以数字卡片展示，会产生以下问题：

- 信息密度过高。
- 用户不知道哪个数据最重要。
- 页面容易变成“数字堆叠”，缺少洞察感。
- 数据可读性不足，不能快速判断学习状态。

### 3. 图表类型需要进一步匹配数据语义

不同数据适合不同图表：

| 数据类型 | 不推荐 | 推荐 |
|---|---|---|
| 正确率 / 完成度 | 普通文本数字 | 进度环 / 环形指标 |
| 学科占比 | 多个数字卡片 | 饼图 / 环形图 |
| 近 7 天趋势 | 静态 KPI | 折线图 / 面积图 |
| 各科目题量对比 | 饼图 | 横向柱形图 |
| 查看答案率 / 放弃率 | 饼图 | 水平进度条 |
| 复习风险 | 复杂图表 | 风险卡片 + 优先级标签 |

当前页面如果图表选择不准确，会导致：

- 图表看起来有了，但信息解释力不足。
- 用户无法快速判断偏科、学习节奏、复习风险。
- 部分图表只起装饰作用，没有实际分析价值。

### 4. 近 7 天趋势表达需要更自然

近 7 天趋势是学习统计页最重要的数据之一，应该帮助用户回答：

- 最近是否有持续学习？
- 今天是否比前几天多做题？
- 正确率是否稳定？
- 是否出现学习断档？
- 是否需要复习调整？

如果使用过重的柱形图、胶囊柱、装饰性柱形，可能出现：

- 视觉占比过大。
- 与学习产品气质不符。
- 小程序窄屏下容易拥挤。
- 用户更关注趋势，不一定关注单日柱形高度。

因此，趋势区应优先使用：

- 折线图
- 面积折线图
- 时间轴
- 简洁摘要卡

### 5. 学科分布需要同时表达“占比”和“正确率”

学科数据通常包含：

- 学科名称
- 做题数量
- 占比
- 正确率
- 学习时长

如果只展示占比，会缺少质量判断。

如果只展示正确率，又看不出投入量。

因此学科分布区域需要同时表达：

- 哪个学科做得最多
- 哪个学科正确率较低
- 是否偏科
- 是否需要调整复习优先级

### 6. 学习行为数据需要更像“提醒”而不是“统计”

学习行为包括：

- 平均答题用时
- 查看答案率
- 放弃率

这些数据不是单纯展示给用户看的，而是用于提示学习习惯。

例如：

- 查看答案率过高：可能说明知识点不熟。
- 放弃率过高：可能说明题目难度或掌握程度有问题。
- 平均用时过长：可能说明解题速度不足。

因此这一块应避免复杂图表，推荐使用：

- 水平进度条
- 行为说明
- 轻量风险色
- 简短文字提示

### 7. 复习风险区域需要行动导向

复习风险数据包括：

- 高频遗忘
- 长期未掌握
- 假掌握

这些不是普通统计，而是学习系统应主动提醒用户处理的内容。

当前如果只是展示数字，用户可能不知道下一步该做什么。

优化方向：

- 强调优先级。
- 明确风险含义。
- 引导用户去复习。
- 避免只用颜色表示风险。

### 8. 空状态与加载状态需要更有学习产品感

学习统计页可能出现：

- 新用户无数据
- 某学科无数据
- 近 7 天无趋势
- 行为数据为空
- 接口加载失败

当前空状态如果只是“暂无数据”，会显得生硬。

优化方向：

- 告诉用户为什么暂无数据。
- 告诉用户如何产生数据。
- 保持语气简洁，不做营销式文案。

示例：

```text
暂无趋势数据
连续练习后会形成学习曲线
```

## 四、可优化项

## P0：必须优化项

### 1. 明确页面主视觉方向

推荐方向：

> 低饱和学习数据手账感 + 专业数据看板结构

不采用：

- AI 科技大屏
- 高饱和渐变
- 重玻璃拟态
- 复杂动态效果
- 紫色 AI 风
- 过度装饰性图形

应采用：

- 暖白背景
- 低饱和蓝灰
- 柔和绿色
- 温和琥珀色
- 简洁卡片
- 轻阴影
- 数据优先

### 2. 重构学习统计页信息层级

页面应从“数据罗列”调整为“学习洞察”。

推荐优先级：

1. 今天学得怎么样
2. 最近 7 天是否稳定
3. 学科分布是否均衡
4. 学习行为是否健康
5. 哪些内容需要复习

### 3. 趋势区优先使用折线图

近 7 天数据建议以折线图为主，而不是柱形图为主。

推荐结构：

```text
近 7 天走势
├─ 折线 / 面积图
│  ├─ 蓝色：刷题量
│  └─ 绿色：正确率
├─ 今日摘要
│  ├─ 今日题量
│  ├─ 今日正确
│  └─ 待复习
└─ 时间轴辅助信息
   ├─ 日期
   ├─ 题量
   └─ 正确率
```

### 4. 学科分布使用环形图 + 列表

推荐结构：

```text
学科分布
├─ 环形图：各学科做题占比
└─ 学科列表
   ├─ 学科名
   ├─ 题量
   ├─ 占比
   └─ 正确率
```

环形图用于看占比，列表用于看详细信息。

### 5. 行为分析使用水平进度条

推荐结构：

```text
学习行为
├─ 平均答题用时
├─ 查看答案率：水平条
└─ 放弃率：水平条
```

原因：

- 百分比数据适合水平条。
- 移动端展示稳定。
- 不需要复杂图表。
- 读数清晰。

## P1：建议优化项

### 1. 增强今日表现区域

今日表现建议作为页面前半部分的重点区域。

推荐展示：

- 今日刷题
- 今日正确
- 今日用时
- 待复习

每个数据应有明确文字标签，不能只依赖颜色。

### 2. 增加“学科做题数量对比”

如果接口数据支持，可以增加横向柱形图：

```text
各科做题对比
数学二  ████████  120题
408     ██████    85题
英语    ███       42题
```

原因：

- 比饼图更适合比较绝对数量。
- 可以直观看出偏科。
- 横向柱形更适合小程序窄屏。

### 3. 优化复习风险文案

复习风险区域建议从“统计项”改为“行动提醒”。

例如：

```text
复习风险
优先处理高频遗忘和假掌握内容
```

风险项：

- 高频遗忘
- 长期未掌握
- 假掌握

### 4. 统一卡片头部样式

每个模块建议统一：

```text
标题
辅助说明
右侧轻量标签
```

示例：

```text
近 7 天走势        Line
蓝色面积代表题量，绿色折线代表正确率
```

但右侧标签不宜过多英文科技感，应轻量使用。

## P2：后续可优化项

### 1. 图表交互增强

后续可以考虑：

- 点击某天查看详情
- 点击学科跳转到该学科错题
- 查看趋势更多天数
- 图表 tooltip

本轮不建议做，避免改业务逻辑。

### 2. 深色主题适配

任务文档提到：

> 支持深色/浅色主题（如项目已支持）

当前如果项目没有完整主题机制，不建议本轮强行加入深色主题。

- 需要全局 token 支持。
- 需要逐页验证。

建议：

- 本轮只保证浅色主题高质量。
- 后续如果项目正式支持主题机制，再做深色主题。

### 3. 动效与骨架屏

可以后续加入：

- 加载骨架屏
- 图表淡入
- 卡片轻微过渡

但本轮不建议过度动画。

## 五、推荐图表方案

### 1. 总正确率 / 学习进度

推荐图表：

```text
进度环 / 环形指标卡
```

适合数据：

- 总正确率
- 总完成度
- 今日目标完成度

展示方式：

```text
       78.5%
      总正确率
```

推荐颜色：

- 主色：`#5B7B9A`
- 背景环：`#EDF1F5`

原因：

- 一眼能理解状态。
- 比纯数字更直观。
- 符合学习产品“进度反馈”语义。

### 2. 学科占比

推荐图表：

```text
环形图
```

适合数据：

- 数学二占比
- 408 占比
- 英语占比

展示方式：

```text
左侧：环形图
右侧：学科 legend + 题量 + 正确率
```

推荐颜色：

```text
数学二：#5B7B9A
408：#C49A6B
英语：#6B9B6B
其他：低饱和辅助色
```

原因：

- 占比关系直观。
- 适合移动端。
- 与总正确率进度环形成视觉统一。

### 3. 近 7 天刷题趋势

推荐图表：

```text
折线图 / 面积折线图
```

适合数据：

- 每日刷题量
- 每日正确率

展示方式：

```text
蓝色面积：刷题量
绿色折线：正确率
```

原因：

- 趋势数据最适合折线。
- 可以观察学习节奏。
- 比柱形图更轻、更学习产品化。

### 4. 学习时长趋势

推荐图表：

```text
折线图
```

适合数据：

- 每日学习时长
- 近 7 天学习时长变化
- 近 30 天学习时长变化

原因：

- 学习时长是连续变化数据。
- 折线更适合表达趋势。
- 可与刷题量趋势分区展示，避免图表过载。

### 5. 各科目做题数量对比

推荐图表：

```text
横向柱形图
```

适合数据：

- 各学科做题量
- 各题型做题量

展示方式：

```text
数学二  ██████████  120题
408     ███████     80题
英语    ████        40题
```

原因：

- 对比绝对数值清晰。
- 横向更适合小程序屏幕。
- 科目名称不容易被挤压。

### 6. 行为分析

推荐图表：

```text
水平进度条
```

适合数据：

- 查看答案率
- 放弃率

展示方式：

```text
查看答案率  24%  █████
放弃率      8%   ██
```

原因：

- 百分比数据适合进度条。
- 信息清楚，不需要复杂图形。
- 可以配合风险色但不只依赖颜色。

### 7. 复习风险

推荐展示：

```text
风险指标卡
```

适合数据：

- 高频遗忘
- 长期未掌握
- 假掌握

展示方式：

```text
高频遗忘       12
长期未掌握      5
假掌握          3
```

原因：

- 风险数据需要行动导向。
- 不适合复杂图表。
- 应突出优先级和复习提醒。

## 七、视觉设计规范

### 1. 色彩

继续使用项目现有设计系统：

```text
页面背景：#F7F5F0
卡片背景：#FFFFFF
主色：#5B7B9A
主色浅背景：#EDF1F5
成功色：#6B9B6B
成功浅背景：#EFF5EF
警告色：#C49A6B
警告浅背景：#F5F1EB
风险色：#C47A7A
风险浅背景：#F5EFEF
主文字：#2D3E50
次文字：#6B7B8D
提示文字：#9AABBA
边框：#E8E5E0
```

### 2. 圆角

建议：

```text
页面主卡片：24rpx - 28rpx
普通卡片：20rpx - 24rpx
小标签：999rpx
图表容器：20rpx - 24rpx
```

### 3. 阴影

采用轻阴影：

```text
0 6rpx 28rpx rgba(43, 60, 80, 0.06)
```

避免：

- 多层重阴影
- 强浮层感
- 玻璃拟态 blur
- 强科技大屏光效

### 4. 字体层级

建议：

```text
页面标题：38rpx - 44rpx
模块标题：30rpx - 32rpx
核心数字：34rpx - 44rpx
正文说明：24rpx - 26rpx
辅助文字：20rpx - 22rpx
```

### 5. 图表风格

图表应：

- 低饱和
- 简洁
- 有文字说明
- 不只依赖颜色
- 不过度装饰
- 保持移动端可读

## 十、实现原则

### 1. 不新增依赖

不引入：

- ECharts
- F2
- AntV
- icon 库
- npm 图表库

图表使用微信小程序原生 Canvas 绘制。

### 2. 不改业务接口

保持：

```js
api.get('/stats/dashboard')
```

不改：

- API 路径
- 请求参数
- 数据结构来源
- 登录鉴权逻辑

### 3. 只做展示字段预处理

允许在 `dashboard.js` 中增加展示辅助字段，例如：

```js
_accPct
_accClass
_sharePct
_color
_shortDate
_viewRatePct
_abandonRatePct
```

这些字段只用于页面展示，不影响业务数据。

### 4. 保留关键小程序绑定

必须保留：

```text
wx:if
wx:for
wx:key
canvas-id
id
bindtap
```

尤其是 canvas：

```text
subject-donut-canvas
trend-line-canvas
```

如果后续新增图表，应明确 canvas-id，不与现有 canvas 冲突。

## 十一、风险评估

### 1. Canvas 真机渲染风险

风险：

- canvas 尺寸获取失败
- 微信开发者工具正常但真机不显示
- 高 DPI 下模糊
- 页面 setData 后绘制时机不稳定

控制方式：

- 使用 `wx.createSelectorQuery().in(this)` 获取尺寸。
- 在 `setData` callback 后绘制。
- 必要时用短延迟等待布局完成。
- 空数据时不绘图。

### 2. 小屏横向溢出风险

风险区域：

- 学科 legend
- 趋势时间轴
- 三列摘要卡
- KPI 数字过长

控制方式：

- 使用 `min-width: 0`
- 文本必要时 ellipsis
- 数字使用较小 compact 样式
- 避免固定过宽布局

### 3. 图表信息过载风险

风险：

- 同一区域展示太多指标。
- 折线、柱形、卡片全部堆在一起。
- 用户不知道重点。

控制方式：

- 每个模块只表达一个主要问题。
- 图表下方摘要不要超过 3 个。
- 辅助说明使用短句。

### 4. 风格偏离风险

风险：

- 过度科技感
- 过度 AI 化
- 强渐变
- 高饱和色
- 装饰图形抢数据

控制方式：

- 使用现有设计系统色。
- 保持暖白背景。
- 使用轻阴影。
- 不使用深色大屏风格。

## 十二、验证清单

### 1. 静态验证

需要检查：

```bash
node --check miniprogram/pages/dashboard/dashboard.js
```

```bash
git diff --check -- miniprogram/pages/dashboard/dashboard.wxml miniprogram/pages/dashboard/dashboard.wxss miniprogram/pages/dashboard/dashboard.js
```

检查关键内容：

- 无 WXML 明显语法错误。
- 无 WXSS trailing whitespace。
- JS 无语法错误。
- canvas-id 未写错。
- 没有误改 API 请求。
- 没有新增依赖。

### 2. 小程序开发者工具验证

需要验证：

- 学习统计页能正常打开。
- 加载态正常。
- 数据加载成功后页面正常渲染。
- 学科环形图正常绘制。
- 趋势折线图正常绘制。
- 空数据时不报错。
- 页面无横向滚动。
- 卡片间距正常。
- 小屏下文字不明显挤压。

### 3. 真机验证

建议真机检查：

- canvas 是否清晰。
- 滚动是否流畅。
- 卡片阴影是否过重。
- 趋势时间轴是否拥挤。
- 图表颜色是否可读。
- 顶部 Hero 是否与页面整体融合。

### 4. UI/UX 验证

检查：

- 信息层级是否清晰。
- 用户能否快速看懂今日表现。
- 用户能否看懂近 7 天趋势。
- 用户能否看出学科分布。
- 用户能否识别复习风险。
- 是否避免只靠颜色表达状态。
- 页面是否符合简洁、专业、现代、学习产品氛围。
