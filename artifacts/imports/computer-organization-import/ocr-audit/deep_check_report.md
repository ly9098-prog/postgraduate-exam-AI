## 2. 类A：题干内嵌选项行（23 题，high）

**现象**：`parsed_content.text`（题干字段）末尾嵌入了 `A.xx / B.xx / C.xx / D.xx` 选项行。小程序/管理端渲染时题干（来自 text）与选项（来自 parsed_options）分别渲染，**选项会在题干里重复显示一次**。

- **连续块 p111–p135（22 题）**：ids `732 733 734 735 736 737 738 740 741 742 743 744 745 746 748 749 750 751 752 753 754 755`（p118 id=739 第一轮已修，属同一块）。
- **p16 id=603**：题干尾部残留孤立 `A.`（首个选项标记碎片）。
- 其中**嵌入顺序乱序 8 题**：`738 740 744 745 748 749 751 755`（如 id=738 嵌入为 `D.溢出 / C.1 0101010 / A.11000000 / B.0 0100100`，原文顺序 A,B,C,D）。
- 该块 `parsed_options` 字母→内容经逐题对照 **均正确**（不含下节 C 类），故修复=从题干剥离选项行即可。

**块内额外内容丢失（同块，一并修复）**：
- **id=740**：题干 `unsigned short usi 执行` 缺 `= si;`（OCR：`unsigned short usi = si;\n执行`）。

- **id=746**：代码用 ```` ```text ```` 围栏包裹（OCR 无围栏），格式与 737/740 等不一致（低）。

**公式/指数（3 题）**：

## 13. 局限

1. **对照基准同为该 OCR 源**：`backend-ocr/remote/` 与 DB 同源于 PaddleOCR-VL，罗马字形、上下标压平等歧义无法仅凭文本定稿（如 id=755）。
2. **无独立第二 OCR / 无原页图像访问**：本会话无法直接查看页面渲染图；`×` 丢失类通过模式扫描（`\d+K\d`）已全量捕获，但「OCR 与 DB 同时压平」的上标场景（如 id=1003 的 B/C `0.97x109`）可能仍有个别漏网，需原图核验。
3. **箭头丢失**：仅能发现「OCR 有箭头而 DB 没有」的题；若 OCR 也未捕获箭头，文本无法检出。
