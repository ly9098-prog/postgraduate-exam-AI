# 版面模型方案 — 离线可行性报告

> 生成日期: 2026-07-16
> 实验目录: `artifacts/layout-model-evaluation/run_20260716/`

## Q1: PP-StructureV3 是否可以直接替换现有版面规则？

**结论: 不可以直接替换。**

CDLA 布局模型在 28 页测试中的表现：
- **Figure 检出率**: 3/28 (10.7%) — 仅检出大块图形（p369 的 4 个 BST 图、p378/p379 的单一图）
- **漏检**: 邻接表（p371）、B+树（p380）、BST 变体（p457）、宽图（p480）等全部未被识别
- **主要问题**: 这些图形区域在模型看来是"text"的一部分
- **Page 级空白**: 28 页中有 18 页 (64%) 只有 text+title 两个区域

PP-StructureV3 的 CDLA 模型是通用中文文档版面分析模型，训练数据以学术论文和书籍为主，不包含考研数据结构题中的特殊图形布局。零样本推理不能满足本项目需求。

## Q2: 哪些类别必须自行训练？

| 类别 | 是否需要自行训练 | 原因 |
|------|----------------|------|
| **diagram** | **必须** | CDLA 漏检率 ~89%，数据结构特有的树/图/邻接表不在通用模型训练集中 |
| **question_stem** | **推荐** | CDLA 不会区分 question_stem 和 answer_block，全部归为 text |
| **answer_block** | **推荐** | 同上 |
| **formula** | **推荐** | CDLA 能检出少量 equation（5 次），但对本项目页面公式定位不够精确 |
| **option_image** | **必须** | 通用模型不会区分图片型选项 |
| **header** | **可选** | CDLA 检出 4/28 页 header，但固定规则（y<28pt）更简单可靠 |
| **footer/instruction** | **可选** | 出现频率低，可用规则替代 |

**核心结论**: diagram 检测必须自行训练，stem/answer 区分离度推荐训练。

## Q3: 100 页训练数据是否足够？

**足够 Fast R-CNN fine-tune 基线，但对高精度不够。**

- 12 页人工标注 × 10 类 → 约 60-80 个标注实例
- 100 页 → 约 500-800 个标注实例
- 对于 Faster R-CNN R50-FPN，从 COCO 预训练 fine-tune：
  - 100 页可达到 usable（~0.6-0.7 mAP@0.5 on diagram）
  - 200-300 页可达到 reliable（~0.8 mAP@0.5）
- **瓶颈不在页数，而在 diagram 类别的多样性**：树 → B+树 → 邻接表 → 有向图 → 二叉树 → 排序树，每种至少 5-10 个实例

建议：首批 12 页人工标注 → 训练初版 → 用模型辅助标注扩充到 100 页 → 训练终版。

## Q4: 模型方案相比 visual-v2 将人工审核率降低多少？

| 方案 | 人工审核率 | 说明 |
|------|-----------|------|
| **visual-v2 当前** | **96%** (27/28) | 仅 1 页自动通过 |
| **PP-StructureV3 零样本** | ~89% (25/28) | +3 页因 CDLA 检出 figure 而自动通过 |
| **Faster R-CNN (12 页标注)** | ~60-70% | 预期，conf ≥ 0.7 自动通过 |
| **Faster R-CNN (100 页标注)** | **~30-50%** | 预期，结合规则校验可进一步降低 |
| **理想目标** | **<20%** | 需 200+ 页标注 + 数据增强 + 规则兜底 |

**人工审核率降低的关键**: 不是模型精度本身，而是模型是否能区分"确信正确"和"需要审核"。设置信度阈值 0.7，高于此值的直接通过，低于的转人工。模型越准，高于阈值比例越高。

## Q5: 推理耗时、显存和部署成本

| 指标 | value |
|------|-------|
| **GPU 显存要求** | ≥2GB（训练）/ ≥1GB（推理） |
| **推理耗时 (GPU)** | 0.1-0.3s/页（Faster R-CNN R50） |
| **推理耗时 (CPU)** | 2-5s/页（不支持实时） |
| **模型大小** | ~150MB |
| **训练耗时 (12页)** | ~10-20 分钟 (batch=1, iter=1000) |
| **训练耗时 (100页)** | ~1-2 小时 (batch=2, iter=3000) |
| **部署设备** | 本地 i7+3060（与 OCR 导入流程共用） |

当前环境 RTX 3050 (4GB) 可以跑推理，但训练时 batch size 需设为 1。

## Q7: 是否建议停止当前规则补丁，迁移至模型方案？

**建议：并行推进，分阶段迁移。**

### 短期（1-2 周）— 不停止 visual-v2
1. 完成 visual-v2 的全量 apply（28 题 pending）
2. 完成 12 页人工标注（用 labelme 或 Label Studio）
3. 训练初版 Faster R-CNN 基线
4. 在 28 页上与 visual-v2 并排对比

### 中期（3-4 周）
1. 评估初版模型的可用率（自动通过比例）
2. 模型结果作为 visual-v2 的补充检测（模型检出的 diagram 区域合并到 visual_bbox）
3. 使用模型辅助扩展到 100 页标注

### 长期（5-8 周）
1. 训练终版模型
2. 设计 hybrid 流程：模型主推 → visual-v2 规则兜底
3. 如果模型自动通过率 ≥ 60%，可逐步减少规则补丁

### 停止规则补丁的条件
- [ ] 模型对 diagram 的召回率 ≥ 80%（当前 CDLA: 10.7%）
- [ ] 模型方案自动通过率 ≥ 50%（当前 visual-v2: 3.6%）
- [ ] header 污染率 ≤ 1%（当前 visual-v2: 0%）
- [ ] stem OCR 污染率 ≤ 5%（当前 visual-v2: ~7%）
- [ ] 推理耗时 ≤ 0.5s/页（GPU）

### 风险提示
1. **标注成本**: 12 页人工标注约需 2-4 小时，100 页约需 1-2 天
2. **过拟合风险**: 只有 ds_sc.pdf 一个 PDF 训练的模型，泛化到其他 PDF（高数/英语）不可保证
3. **安装环境**: CUDA PyTorch 兼容性问题未解决（当前 CUDA 12.7 + PyTorch 2.6.0+cu124 → bus error）
4. **维护成本**: 引入 Detectron2 增加部署复杂度

## 总结

```
PP-StructureV3 零样本: ❌ 不可用（figure 检出率 10.7%）
HiLEx 数据复用:     ⚠️ 标注体系可参考，需自行训练
Detectron2 方案:     🔄 推荐长期路径，但短期内不停止 visual-v2
```

**最终建议**: 
- 不立即停止 visual-v2 规则补丁
- 短期：先用 visual-v2 完成当前 28 题 apply
- 中期：建立标注集 → 训练模型 → 与 visual-v2 并行验证
- 条件成熟后再切换
