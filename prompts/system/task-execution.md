# 任务执行规范

> 状态：早期任务执行 Prompt，不是当前最高规则。已按 2026-11-02 上线后稳定性治理口径更新；仍以根目录 `AGENTS.md`、`docs/project/PROJECT_RULES.md` 和代码为准。

> 如何拆分任务、编码、测试、提交。

---

## 任务拆解

1. 先读 `prompts/README.md`、当前任务入口和有限收口账本；没有明确授权的任务不要自行扩张
2. 复杂任务按完整业务链路拆为可验证批次，每批写明消费者、兼容边界、验证方法和退出条件
3. 每批完成后运行受影响测试与静态检查；高风险改动补迁移、并发、故障或真实环境验收计划
4. 每批一个目的明确的本地提交；生产部署、迁移、推送和用户数据操作须单独授权

## 编码规范

- Python 3.11+，类型注解全覆盖
- 新增或拆出的业务模块遵循 300 行 / 50 行预算；既有超限模块按有限重构账本处置
- 路由只做参数校验，业务下沉到 services/
- 抽象按需引入，必须有真实复用或测试收益；不为形式添加无消费者的接口层
- 保持模块职责清晰、依赖方向明确，避免跨层直接依赖和无边界共享
- 避免无意义的属性包装和隐式副作用
- 不用 `__init__.py` 做重导出
- 重复逻辑先确认语义是否一致，再提取；不要为了消除表面重复制造错误耦合

## 数据库规范

- 索引以真实查询和执行计划为依据，不为猜测堆索引，也不让生产慢查询长期存在
- 迁移以前向演进和审计为主；生产执行前先备份，恢复/回退走已验证流程
- 复杂查询先核对执行计划和数据量，避免无界 N+1 和过深 join
- CRUD 使用现有 SQLAlchemy 异步 ORM 与 service 边界；没有真实替换需求时不额外引入 repository 层

## AI 模块规范

- 不引入 langchain / llamaindex
- 直接 httpx 调 OpenAI-compatible 网关；模型和凭据经 Admin API 配置于数据库，不写环境变量
- 运行时 AI Prompt 模板集中在 `backend/app/ai/prompts*.py` 并维护版本；Agent/开发 Prompt 在 `/prompts`
- 失败降级优先于重试
- AI/OCR 结果必须经过 `question_imports` 和人工确认，不得直接入库
- AI 不可用时不影响核心刷题流程

## 测试规范

- 不设统一覆盖率百分比门禁，以行为覆盖和可复现验收为准
- 路由、模型、迁移、队列、OCR、AI、安全边界变化必须补对应 API/集成/回归测试
- 纯规则优先单元测试；跨进程、数据库、缓存和外部服务边界按风险补集成或真实替身证据
- 模拟器、真机、隔离环境与生产证据分开记录，不能用低等级证据替代高等级验收
- 每批运行受影响测试和静态检查；领域收口或高风险变更按现有门禁运行完整检查

## Git 提交

```
<type>: <简短描述>
```

type: `feat` / `fix` / `refactor` / `perf` / `docs` / `style` / `test` / `build` / `ci` / `chore` / `revert`

- 只暂存显式路径，不提交无关改动、密钥、运行产物或用户数据
- 不添加 AI attribution，不 push、不改写历史；部署须单独授权

示例：
```
feat: 新增 AI 错题分析接口
fix: 修复复习计划日期重复问题
docs: 更新 API_SPEC.md
```
