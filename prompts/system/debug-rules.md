# Testing Rules — 导入管线系统

> 状态：早期测试 Prompt，不是当前最高规则。已按 2026-11-02 上线后稳定性治理口径更新；以根目录 `AGENTS.md`、`docs/project/PROJECT_RULES.md` 和代码为准。

## 单元测试要求

- 每个阶段的纯规则/核心函数必须有单测，测试放在相邻的现有测试目录
- 纯函数测试不 mock，直接断言输入输出
- 涉及文件 I/O 的测试使用 `tmp_path` fixture（pytest 内置）

## 回归测试

- 每次修改后运行受影响目录/模块的单测；高风险边界补 API、集成或回归测试
- 管线集成测试与功能实现同步维护，不推迟到某个“最后阶段”统一补写
- 测试数据（示例 PDF/Word/Excel）放在现有 fixtures 目录，不使用真实用户数据或生产凭据

## 批次完成测试

每个交付批次按影响范围覆盖以下测试：

| 测试类型 | 描述 |
|---------|------|
| 正常路径 | 标准输入能正确处理 |
| 空输入 | 空文件/空字符串不崩溃 |
| 异常输入 | 乱码/格式错误文件有明确错误提示 |
| 边界值 | 超大文件、超多选项、超长文本 |
| 部分数据 | 缺字段输入能降级处理 |

## 边界测试

- 空文件：0 字节 PDF/Word/Excel
- 无题目的文档（纯文本、目录页）
- 单题文档
- 1000+ 题文档（性能基准测试）
- 混合题型文档（单选+多选+填空+判断混排）

## OCR 脏数据测试

- 包含 OCR 噪声字符的文本（乱码、多余符号、换行异常）
- 公式识别不完整的文本
- 中英文混排的科目标记
- PDF 图片提取产生的空文本

## 证据边界

- 单元测试、集成测试、SQLite、模拟器、真机和生产证据分开记录
- 外部 OCR/AI、Redis、PostgreSQL、worker 和浏览器行为不能用 mock 结果替代
- 未执行的环境项必须标注“未验证”，不得把跳过或部分通过写成全量通过
