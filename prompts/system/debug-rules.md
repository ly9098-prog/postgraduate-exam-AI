# Testing Rules — 导入管线系统

> 状态：早期导入管线 Prompt，不是当前最高规则。以根目录 `AGENTS.md`、`docs/project/PROJECT_RULES.md` 和代码为准。下文里的模型、JWT 天数和目录树可能已过时。

## 单元测试要求

- 每个 stage 的核心函数必须有单测
- 测试文件命名为 `test_<stage_module>.py`，放在 `backend/tests/test_services/`
- 纯函数测试不 mock，直接断言输入输出
- 涉及文件 I/O 的测试使用 `tmp_path` fixture（pytest 内置）

## 回归测试

- 每次修改某个 stage 后，必须运行该 stage 的所有单测
- 管线的集成测试在 stage8 完成后统一编写
- 每个 stage 的测试数据（示例 PDF/Word/Excel）放在 `backend/tests/fixtures/`

## 阶段完成测试

每个阶段完成后必须通过以下测试：

| 测试类型 | 描述 |
|---------|------|
| 正常路径 | 标准输入能正确处理 |
| 空输入 | 空文件/空字符串不崩溃 |
| 异常输入 | 乱码/格式错误文件有明确错误提示 |
| 边界值 | 超大文件、超多选项、超长文本 |
| 部分数据 | 缺字段输入能降级处理 |

## 边界测试

- 空文件：0 字节 PDF/Word/Excel
- 无题目的文档（纯文本、目录页）
- 单题文档
- 1000+ 题文档（性能基准测试）
- 混合题型文档（单选+多选+填空+判断混排）

## OCR 脏数据测试

- 包含 OCR 噪声字符的文本（乱码、多余符号、换行异常）
- 公式识别不完整的文本
- 中英文混排的科目标记
- PDF 图片提取产生的空文本
