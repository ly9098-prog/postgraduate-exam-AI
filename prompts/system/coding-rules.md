# Coding Rules — 导入管线系统

> 状态：早期导入管线 Prompt，不是当前最高规则。以根目录 `AGENTS.md`、`docs/project/PROJECT_RULES.md` 和代码为准。下文里的模型、JWT 天数和目录树可能已过时。

## 代码风格

- Python 3.11+，类型注解全覆盖（函数参数和返回值必须有类型标注）
- 使用 `ruff` 做 lint + format（配置见 `pyproject.toml`）
- 新增或拆出的业务模块遵循 300 行 / 50 行预算；既有超限模块按有限重构账本处置
- 抽象按需引入，必须有真实复用或测试收益；不为形式添加接口/抽象类或 AOP 层
- 保持模块职责清晰、依赖方向明确，避免无意义的包装和隐式副作用

## 禁止硬编码

- 题型映射表、学科映射表、正则模式串必须放在模块顶层的常/变量中
- 不允许在函数内部写死字符串匹配模式
- 运行时 AI Prompt 模板集中在 `backend/app/ai/prompts*.py`；Agent/开发 Prompt 在 `/prompts`；不散落在无关业务代码中
- 普通运行配置走 `app/core/config.py`；AI 模型与凭据经 Admin API 存于数据库，不写环境变量

## 可测试性

- 核心函数必须是纯函数（输入 → 输出，无副作用）或副作用在边界隔离
- 文件 I/O、API 调用必须可 mock / 可注入
- 每个领域批次的核心函数必须可单文件调用测试

## 模块化

- 按领域和职责拆分模块，不跨模块引用内部符号
- 模块间只通过函数调用和返回值通信，不共享全局状态
- 同领域内工具函数可放同文件底部或 `_helper` 前缀函数；公共逻辑有真实复用后再提取

## Prompt 不允许写死

- Prompt 模板中不嵌入业务数据
- 题型列表、学科列表从配置/常量读取，动态拼入 prompt
- 所有 AI 调用走现有统一 AI 客户端/服务边界，不直接在业务代码中构造 http 请求

## AI 逻辑可开关

- AI 修复模块必须有一个全局开关（配置项），关闭后不调用 API
- AI 模块的 import 必须是延迟/条件 import，不影响核心管线启动
- AI 不可用时必须可观测地降级并记录日志/指标，不抛未处理异常阻塞核心流程
