==================================================
一、业务背景
==================================================

当前图片导入通常能够识别题干和 A-D 选项，但经常缺失正确答案。

人工目前需要逐题进入审核池填写答案，效率很低。

需要在审核池的单个导入批次详情中增加：

“快速补充答案”

第一阶段实现手动输入答案串。

第二阶段实现上传“答案页”或“答案解析页”图片，并将识别出的答案匹配到当前批次题目。

本次开发必须优先完成第一阶段。第二阶段可以在第一阶段稳定后继续实现，但两阶段必须共用统一的预览和写入逻辑。

==================================================
二、第一阶段：答案串快速补录
==================================================

1. 功能入口

在后台管理端“审核池 / 导入批次详情”页面增加按钮：

快速补充答案

按钮只作用于当前打开的导入批次。

不得作用于：

- 全部审核池
- 正式题库
- 其他批次
- 当前搜索结果之外但属于其他批次的题目

2. 弹窗结构

点击后打开弹窗，至少包含：

- 当前批次名称或批次 ID
- 当前批次题目总数
- 已有答案数量
- 缺失答案数量
- 答案输入框
- 输入答案数量
- 本次将匹配的题目范围
- 解析预览
- 下一步
- 取消

3. 排序规则

答案必须严格按照：

source_order_index 升序

匹配当前批次题目。

禁止使用：

- 当前表格显示顺序
- 当前分页顺序
- 用户点击列头后的排序
- source_question_no 数值排序
- question_imports 主键排序
- 当前筛选结果顺序

后端必须重新按 source_order_index 获取并锁定目标题目顺序。

需要明确处理：

- source_order_index 为空
- source_order_index 重复
- source_order_index 不连续

出现为空或重复时，不得静默写入，应返回明确异常或进入预览警告。

4. 单选答案输入

主要场景为 A-D 单选题。

以下输入应视为等价：

abcda
ABCDA
AbCdA
A B C D A
A,B,C,D,A
A|B|C|D|A
A
B
C
D
A

解析后统一转换为：

["A", "B", "C", "D", "A"]

写入数据库时统一保存为大写。

连续字符串模式仅允许识别：

A
B
C
D

可根据现有项目数据判断是否还支持 E、F；不要未经检查擅自扩大合法选项范围。

输入中的普通空格、换行、英文逗号、中文逗号、竖线、分号等可作为分隔符清理或解析。

5. 允许只对应前 N 道题

假设当前批次有 100 道题，用户输入 5 个答案：

ABCDA

系统允许将其映射到按 source_order_index 排序后的前 5 道题。

剩余 95 道题不修改。

预览中必须清楚显示：

- 当前批次共 100 道题
- 本次识别 5 个答案
- 将处理前 5 道题
- 剩余 95 道题不修改

不需要强制答案数量等于批次题目总数。

但答案数量不得超过当前批次题目总数。

如果超过，必须禁止提交，并返回明确错误。

6. 已有答案处理

当前规则：

已有答案的题目默认跳过，不覆盖。

但已有答案的题目仍然占用答案串中的原位置。

例：

当前批次前 5 道题中，第 2 题已有答案 D。

输入：

ABCDA

必须映射为：

第1题：写入 A
第2题：输入 B，但原答案为 D，跳过并保留 D
第3题：写入 C
第4题：写入 D
第5题：写入 A

禁止因为第 2 题跳过而将后续答案向前移动。

预览状态至少包括：

- 将写入
- 已有答案，跳过
- 输入答案与已有答案相同，跳过
- 非法答案
- 题目顺序异常
- 题型不支持

默认不提供覆盖已有答案选项。

本次版本严禁批量覆盖已有答案，避免误操作。

7. 多选题支持

多选题可能少量存在。

禁止将无分隔符字符串用于多选题，因为：

ACBDA

无法判断是 5 道单选题还是某道题答案为 AC。

存在多选题时，支持显式分隔格式：

A,AC,B,BCD,D

解析为：

["A", "AC", "B", "BCD", "D"]

多选答案需：

- 转换为大写
- 去重
- 按字母顺序标准化

例如：

CA
AAC
c,a

应根据输入格式和现有答案存储规范，最终标准化为 AC。

必须检查该题实际选项范围。

例如题目只有 A-C 选项，却输入 D，应标记为非法答案。

不要自动猜测或纠正为其他答案。

8. 判断题支持

判断题可能少量存在。

需要先检查现有数据库中判断题答案的真实存储格式。

可以接受的用户输入形式包括：

T / F
TRUE / FALSE
对 / 错
正确 / 错误
√ / ×

但最终必须转换成项目当前已有的统一存储格式。

不得在未检查现有代码和数据格式前自行决定保存 TRUE、FALSE 或 1、0。

9. 题型校验

每个答案写入前必须校验：

- 题型是否支持
- 答案是否合法
- 答案是否超出当前题目选项范围
- 是否已有答案
- 当前题目是否属于目标 batch_id

简答题、填空题等不支持答案串补录的题型：

- 不写入
- 在预览中标记“题型不支持”
- 不影响其他合法题目提交

10. 预览流程

禁止输入答案后直接写数据库。

必须先调用“解析预览”接口，返回每道题的映射结果。

预览表至少返回：

- import_id
- source_order_index
- source_question_no
- 题干摘要
- question_type
- 原答案
- 输入答案
- 标准化后的答案
- 处理状态
- 状态说明
- will_update
- validation_errors

预览汇总至少返回：

- batch_total
- parsed_answer_count
- target_question_count
- remaining_question_count
- writable_count
- skipped_existing_count
- unsupported_count
- invalid_count
- warning_count

前端展示示例：

顺序 | 原题号 | 题干摘要 | 原答案 | 新答案 | 状态
1    | 01    | 栈和队列…… | 空 | A | 将写入
2    | 02    | 循环队列…… | D  | B | 已有答案，跳过
3    | 03    | 二叉树……   | 空 | C | 将写入

11. 提交规则

提交时前端不能直接传一组 question_import_id 和答案作为最终依据。

建议前端提交：

- batch_id
- 原始答案文本
- 预览生成的 preview_token 或 operation_token
- 可选的解析配置版本

后端必须重新校验：

- token 是否属于当前管理员
- token 是否属于当前批次
- token 是否过期
- 批次题目顺序是否发生变化
- 原答案是否发生变化
- source_order_index 是否发生变化

防止预览后其他管理员编辑题目导致错误写入。

若现有项目不适合保存 preview_token，可采用：

- 预览结果哈希
- batch version
- optimistic locking
- 更新时间戳校验

选择与当前架构最一致的方式。

12. 数据库更新

仅更新满足以下条件的记录：

- 属于当前 batch_id
- 在前 N 个目标题目范围内
- 当前答案为空
- 标准化答案合法
- 题型受支持

不得更新已有答案。

建议一次提交使用数据库事务：

- 合法项全部写入
- 单条非法项在预览阶段排除
- 数据库异常时整体回滚

需要评估是“部分成功”还是“全有或全无”。

推荐策略：

预览确认后，只提交 will_update=true 的合法记录；
这些合法记录在一个事务中全部成功或全部回滚。

三、第二阶段：答案/解析图片导入
==================================================

第二阶段必须复用第一阶段的：

- 字段合法性校验
- 已有答案跳过

1. 图片类型

支持识别以下页面类型：

- question：题目页
- answer：纯答案页
- answer_analysis：答案和解析页
- analysis：纯解析页
- mixed：混合页
- unknown：无法确定

示例答案解析页格式：

一、单项选择题

01. B
栈和队列的逻辑结构都是相同的，都属于线性结构，只是它们对数据的运算不同。

02. C
首先栈是一种线性表，所以选项 B、D 错……

应提取为：

[
  {
    "question_no": "01",
    "answer": "B",
    "analysis": "栈和队列的逻辑结构……"
  },
  {
    "question_no": "02",
    "answer": "C",
    "analysis": "首先栈是一种线性表……"
  }
]

2. 上传模式

图片上传时提供选项：

- 仅导入答案
- 同时导入答案和解析

默认：

仅导入答案

因为项目后续已有 LLM 生成解析能力。

3. 解析字段写入规则

当选择“同时导入答案和解析”时：

- 原答案为空：允许写入答案
- 原答案已有：跳过答案
- 原解析为空：允许写入解析
- 原解析已有：跳过解析

答案和解析分别判断。

允许出现：

- 答案跳过，但解析写入
- 答案写入，但解析跳过
- 两者都写入
- 两者都跳过

默认不得覆盖已有答案或已有解析。

4. 题号匹配

图片答案优先按题号匹配当前批次。

题号格式需要归一化：

01.
01、
第01题
1．
1)
（1）

统一为可比较的题号值。

匹配顺序：

1. 当前 batch_id 内 source_question_no 精确匹配
2. 去除前导零后匹配
3. 标准化中文/英文标点后匹配
4. 无法匹配则进入未匹配列表
5. 禁止自动跨批次匹配
6. 默认禁止静默按顺序回退

如果允许顺序回退，必须由用户在预览页面显式启用，并显示高风险警告。

5. OCR 与规则优先级

优先复用现有 OCR Pipeline、页面分类器、question_splitter、answer_matcher 等能力。

对于格式稳定的：

01. B
解析文本

优先使用规则拆分：

- 题号
- 答案
- 到下一题题号前的文本作为解析

LLM 仅用于：

- OCR 文本结构严重混乱
- 题号与答案无法通过规则确定
- 混合页结构恢复

不得让 LLM 无依据生成答案。

LLM 只能从 OCR 原文中提取和结构化答案，不能推理题目正确答案。
