# 1. 产品定位

## 1.1 核心定位

将当前项目从“通用考研刷题系统”进一步收敛为：

> **围绕 408 知识掌握、遗忘、薄弱点、错因与真题选择题训练构建的个性化学习系统。**

当前阶段不追求继续增加数学、英语、政治等科目的学习功能，优先把 408 做深。

## 1.2 408 范围

408 一级科目下重点维护四个核心子科目：

1. 数据结构
2. 计算机组成原理
3. 操作系统
4. 计算机网络

其他科目：

- 暂停产品层面的继续开发；
- 小程序默认不暴露入口；
- 数据与通用代码不删除；
- 优先使用现有 `Subject.is_active` / 科目树机制进行停用或隐藏；
- 保留未来重新启用的可能，不因本轮 408 专项化制造不可逆的数据迁移。

# 2. 全局硬约束

以下约束优先级高于单个功能需求。

## G-01：408 优先，暂不横向扩科

- 当前所有新增学习功能首先围绕 408 设计。
- 不为其他科目单独建设同等功能。
- 通用底层能力可以保持科目无关，但前台产品体验以 408 为中心。

## G-02：真题套卷 / 模拟考试仅做选择题部分

这是本轮规划的明确产品边界。

### V1 支持

- **仅纳入选择题作答场景。**
- V1 以项目现有标准题型 `single_choice` 为主。
- 若未来确认某类 408 题源确实需要 `multiple_choice`，必须单独评审后再加入，不自动扩大 V1 范围。
- 手机端完成选项选择、切题、标记、交卷、自动判分和结果分析。

### V1 明确不做

- `subjective` 主观题在线作答；
- 简答题、计算题、综合应用题的手机输入；
- OCR 手写答案识别；
- AI 主观题评分；
- 人工阅卷工作流；
- 填空题考试交互；
- 在试卷模块中为了“凑完整试卷”展示不可作答的主观题占位。

### 产品文案要求

前台应明确表达“真题选择题”“选择题模拟”等概念，避免让用户误认为系统覆盖完整 408 试卷全部题型。

## G-03：移动端优先

- 所有学习功能先保证微信小程序可完成核心闭环。
- 不设计依赖大屏、复杂拖拽或长文本输入的核心学习流程。
- 单次关键操作尽可能控制在 1~2 次点击内。

## G-04：复用现有能力，避免重复造轮子

当前项目已经具备题库、题目版本、知识点、错题、复习、自适应学习、推荐日志、知识图谱、学习统计、AI、RBAC、审计日志等基础设施。

新增功能应优先复用：

- `questions` / `question_versions`
- `subjects`
- `knowledge_points` / 知识点关系
- `practice_records` / `practice_sessions`
- `wrong_questions`
- `review_schedules` / `review_records`
- mastery / knowledge states
- adaptive-learning
- recommendation
- AI Gateway
- 管理后台 RBAC / audit log

只有在语义明显不同的领域（例如“正式试卷、一次考试尝试、试卷固定题序”）才新增独立模型。

## G-05：历史题目版本必须可追溯

真题套卷、模考记录和历史作答结果不得因管理员后续编辑题目而悄悄变化。

原则：

- 发布的试卷需要固定题目顺序和所使用的题目版本；
- 历史考试记录保留提交时的题目版本语义；
- 后续题目纠错时，需要明确“仅影响未来考试”还是“创建新试卷版本”；
- 不允许直接用当前可变 `Question` 投影重算历史成绩。

## G-06：新功能必须进入可观测、可测试、可回滚体系

每个 Phase 至少包含：

- 数据迁移；
- API 测试；
- 核心业务单元/集成测试；
- 小程序核心交互回归；
- 管理后台 build；
- OpenAPI / TypeScript contract（涉及 API 时）；
- 权限与审计（涉及 Admin 写操作时）；
- 灰度/回滚说明。

# 3. 当前能力基线与复用判断

根据当前工程快照，后续规划按以下事实作为基线：

| 能力 | 当前情况 | 后续策略 |
|---|---|---|
| 普通刷题 | 已有 random / smart / similar / sequential 等模式 | 继续复用 |
| 题目版本 | 已有 `QuestionVersion` / `current_version_id` 语义 | 真题试卷必须利用版本固定能力 |
| 刷题会话 | 已有 `PracticeSession`，并有完整提交幂等 | 普通刷题继续使用；考试建议独立事实表 |
| 错题本 | 已有 | 真题错题应能进入错题/复习体系 |
| 今日复习 | 已有 | 智能学习中心直接聚合 |
| 自适应概览 | 已有 `/api/v1/adaptive-learning/overview` | 前台产品化 |
| 困难题 | 已有 `/api/v1/adaptive-learning/hard-questions` | 前台产品化 |
| 自适应知识路径 | 已有 `/api/v1/adaptive-learning/knowledge-path` | 前台产品化 |
| 用户知识状态 | 已有 `/api/v1/knowledge/states` | 408 掌握地图直接复用 |
| 薄弱知识点 | 已有 `/api/v1/knowledge/weak-points` | 首页与地图复用 |
| 推荐反馈 | 已有曝光/点击/作答反馈入口 | 智能学习中心继续接入 |
| 知识图谱 | 后端与管理后台已有 | 增加面向学生的可读版本 |
| AI 讲解 | 已有 | 升级为 408 专项交互 |
| 公式卡 | 已有 | 后续可扩为 408 速记卡 |
| 真题试卷领域 | 当前未形成独立 `ExamPaper` 领域 | 新建 |
| 错因 taxonomy | 当前没有统一用户错因事实源 | 新建 |

### 关键架构判断

“真题套卷 / 模拟考试”不应简单等同于普通 `PracticeSession`：

- 普通练习强调推荐和刷题；
- 考试强调固定试卷、固定题序、开始/交卷状态、计时、历史成绩和试卷版本。

因此考试应建立独立事实源，再与 mastery / wrong-question / stats 体系做明确的数据联动。

# 6. P0 — 408 智能学习中心

## TASK 408-HUB：Today / Smart Study Hub

### 产品问题

首页应该明确回答：

> **“我今天最应该做什么？”**

而不是让用户自己在随机刷题、错题本、报告、复习之间选择。

### 核心输出

首页聚合形成今日建议：

1. 到期复习；
2. 弱项强化；
3. 困难题重练；
4. 智能推荐新题；
5. 下一知识路径节点；
6. 408 四科掌握概览。

### 子任务

#### 408-HUB-BE-01：聚合 API

- [x] 评估是否增加统一 `GET /api/v1/study-hub/overview`。
- [x] 聚合现有 review、adaptive overview、hard questions、weak points、knowledge path 等能力。
- [x] 后端明确任务优先级规则，避免小程序自行拼装业务规则。
- [x] 返回每个任务的 `reason`、预计题量、推荐入口参数。
- [x] 返回稳定的 fallback：新用户、数据不足、知识图谱不足时仍有任务可做。

#### 408-HUB-BE-02：今日推荐决策规则

初始规则建议：

1. 到期复习优先；
2. 近期反复错误知识点优先；
3. 低 mastery 且有足够题量的知识点优先；
4. 困难题重练；
5. 新知识推进；
6. 数据不足时回退到 408 随机练习。

- [x] 所有推荐需要可解释 reason。
- [x] 继续写 recommendation log / feedback。
- [x] 对同一日任务生成保持足够稳定，避免每次刷新完全改变。

#### 408-HUB-MP-01：首页改造

- [x] 首页主卡展示“今日最优先任务”。
- [x] 展示今日总目标、已完成、剩余。
- [x] 展示 408 四科掌握摘要。
- [x] 增加“弱项强化”“困难题重练”“继续知识路径”入口。
- [x] 保留今日复习、错题本、学习报告、番茄钟等入口，但降低决策负担。

#### 408-HUB-MP-02：智能任务落地

- [x] 点击任务后直接带入 subject / knowledge point / question ids / mode。
- [x] 推荐曝光、点击、作答正确性继续回传。
- [x] 完成任务后刷新首页任务状态。

### 验收标准

- 用户打开首页 3 秒内能明确知道下一步该做什么。
- 有历史数据用户能看到真实薄弱知识点驱动的推荐。
- 无历史数据用户仍可正常得到首组任务。
- 今日复习存在时，首页优先级符合预期。
- 推荐入口最终都能进入现有 quiz runner 或对应学习流程。

# 7. P0 — 408 真题选择题 / 模拟考试

## TASK 408-EXAM：Choice-only Exam Domain

### 目标

建立独立于普通刷题的“真题选择题考试”领域，让用户可以完成：

> 选择年份/模拟卷 → 开始 → 连续做选择题 → 交卷 → 自动判分 → 查看四科/知识点/错题分析 → 进入后续复习。

## 7.1 范围再次确认

### V1 只做

- 真题**选择题部分**；
- 选择题模拟卷；
- `single_choice` 自动判分；
- 固定题序；
- 考试计时；
- 手动提前交卷；
- 答题卡；
- 标记待检查；
- 成绩、正确率、耗时、四科分布、知识点分布；
- 错题进入现有错题/复习体系。

### V1 不做

- 主观题；
- 综合应用题在线作答；
- AI 阅卷；
- 手写输入；
- 上传答题纸；
- 人工复核分数；
- “完整 408 总分”的伪计算。

结果页所有分数必须明确是：

> **选择题部分得分 / 本套选择题得分**

不得包装成完整 408 总成绩。

## 7.2 数据模型

建议新领域：

### `exam_papers`

候选字段：

- `id`
- `title`
- `paper_type`：`past_exam_choice` / `mock_choice`
- `year`
- `source`
- `duration_sec`（本选择题模块建议时长，可选）
- `total_choice_score`
- `question_count`
- `version`
- `status`：draft / published / archived
- `is_active`
- `published_at`
- `created_at` / `updated_at`

### `exam_paper_questions`

候选字段：

- `paper_id`
- `question_id`
- **`question_version_id`**
- `position`
- `score`
- `section_subject_id`
- unique(`paper_id`, `position`)
- unique(`paper_id`, `question_id`)（是否强制由专项设计确认）

硬规则：

- V1 发布时只允许满足题型白名单的题目进入试卷；
- 试卷项必须固定 `question_version_id`；
- 已发布试卷修改题目时不能静默替换历史语义。

### `exam_attempts`

候选字段：

- `id`
- `paper_id`
- `paper_version`
- `user_id`
- `status`：in_progress / submitted / expired / abandoned
- `started_at`
- `submitted_at`
- `duration_sec`
- `answered_count`
- `correct_count`
- `score`
- `request_id` / 幂等字段

### `exam_answers`

候选字段：

- `attempt_id`
- `exam_paper_question_id`
- `question_id`
- `question_version_id`
- `selected_answer`
- `is_correct`
- `score`
- `used_time`
- `marked_for_review`
- `answered_at`

### 事实源原则

- `exam_attempts + exam_answers` 是考试事实源。
- 不建议为了省事把整场考试伪装成普通 `PracticeSession`。
- mastery / wrong question 的更新通过服务层显式联动。
- 若当前 mastery 强耦合 `PracticeRecord`，应先抽取统一的“answer event / mastery ingestion”服务，而不是复制判定逻辑。

## 7.3 Public API

建议最少包含：

- [x] `GET /api/v1/exams/papers`
- [x] `GET /api/v1/exams/papers/{paper_id}`
- [x] `POST /api/v1/exams/papers/{paper_id}/attempts`
- [x] `GET /api/v1/exams/attempts/{attempt_id}`
- [x] `PUT/PATCH /api/v1/exams/attempts/{attempt_id}/answers/{item_id}`（保存答案/标记）
- [x] `POST /api/v1/exams/attempts/{attempt_id}/submit`
- [x] `GET /api/v1/exams/attempts/{attempt_id}/result`
- [x] `GET /api/v1/exams/history`

关键要求：

- 开卷时服务端生成 attempt；
- 题目返回不包含正确答案和解析；
- 交卷接口幂等；
- 重复提交返回同一结果；
- 结果使用固定 question version 判分；
- 客户端断线后可恢复 in-progress attempt；
- 所有权限只允许访问本人 attempt。

- 不显示解析；
- 不显示 AI 讲解；

- [x] 历史 attempt 列表。
- [x] 可重新查看结果。

## 7.6 与现有系统联动

- [x] 错因系统完成后，可对考试错题进一步分类。

## 7.7 验收标准

- 一个管理员可以从现有 408 题库创建一套仅选择题的真题卷并发布。
- 用户可以在手机上完整完成选择题考试并自动得到稳定结果。
- 中途退出后可以恢复未交卷 attempt。
- 同一 attempt 重复交卷不会重复记错题、重复加 mastery 或产生多条成绩。

- 任何非允许题型均无法进入 V1 已发布试卷。
- UI 明确说明成绩仅对应选择题部分。

# 9. P1 — 错因分类与学习诊断

## TASK 408-ERROR

### 目标

从“记录错题”升级为“记录错误原因”。

### V1 错因 taxonomy 建议

- `knowledge_gap`：知识点不会
- `concept_confusion`：概念混淆
- `memory_error`：定义/公式记忆错误
- `calculation_error`：计算错误
- `misread`：审题错误
- `reasoning_error`：推理/算法思路错误
- `time_pressure`：时间不足
- `careless`：粗心
- `unknown`：暂未分类

taxonomy 最终命名在专项设计时冻结。

### 数据原则

建议区分：

- AI 建议错因；
- 用户最终确认错因；
- 分类置信度；
- 分类版本。

用户确认结果优先级高于 AI 推断。

### 子任务

#### 408-ERROR-BE

- [x] 新增错因事实表或 wrong question 的独立关联表。

- [x] 错因统计接口。
- [x] 按科目 / 知识点 / 时间窗口聚合。

#### 408-ERROR-AI

- [x] AI 根据题干、选项、正确答案、用户答案、解析、知识点给出建议错因。
- [x] AI 分类失败时不得阻塞交卷。
- [x] 分类进入异步任务更合适时，不影响即时结果页。

#### 408-ERROR-MP

- [x] 错题详情允许查看/修改错因。
- [x] 练习结果页可快速确认错因。
- [x] 学习报告增加错因分布。
- [x] 显示近期错误模式变化。

### 验收标准

# 10. P1 — 408 专项 AI 老师

## TASK 408-AI

### 目标

不继续扩展“万能聊天”，而是提供与 408 学习直接相关的固定能力。

### 推荐操作

在题目详情中提供：

- 为什么这个正确选项对？
- 为什么 A/B/C/D 错？
- 这道题真正考什么？
- 给我一道同类题。
- 给我一道更难的题。
- 帮我串联相关知识点。
- 总结这个知识点的 408 高频陷阱。

### 上下文

AI 可使用：

- 当前题目固定版本；
- 用户选项；
- 正确答案；
- 题目解析；
- 知识点；
- 用户 mastery / weak points；
- 最近相同知识点错误；
- 相关知识图谱邻居。

不得把其他用户数据放入上下文。

### 关键任务

- [x] 为固定动作建立 prompt templates，而非前端自由拼接 prompt。
- [x] 输出结构化 schema，便于小程序展示。
- [x] 保留 AI usage / feedback / token budget。
- [x] 考试进行中禁止调用会泄露答案的 AI 能力。
- [x] 交卷后才允许针对考试题 AI 讲解。

### 验收标准

AI 回答能体现当前用户的 408 学习上下文，而不只是重复题目解析。

### 依赖

- 408-MAP 有助于获得更强的用户知识状态上下文。
- 408-ERROR 有助于针对错因提供建议。
