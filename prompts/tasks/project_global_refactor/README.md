## 内容分工

- `../current_task.md`：简短任务入口，维护当前状态、优先级、卷索引和下一步；不再堆积整段历史。
- `closure-ledger.md`：当前有限调度队列。每个条目写明真实消费者、证据、退出条件和四种终态；真实环境验收单独放在最后。
- `plan.md`：原计划的 §1–§6、阶段清单、验收标准和安全边界；历史进度只作快照，后续目标变化在当前任务入口说明。
- `history-NN.md`：按原文顺序保存执行记录，原章节号、早期“第 N 批”号、提交、验证限制均保留。
- `../context.md`：供接续执行的简短摘要，不复制全部历史或多份结果数字。
- 专项兼容文档说明行为边界，`docs/architecture/refactor-results/` 记录相应批次的命令、数字和哈希。

## 100 批次上限与追加

1. 每份 `history-NN.md` 最多 100 批次。容量按原记录编号计数：单条计 1；例如“§198—§204”按 7 条计，不能只算成一个 Markdown 标题。
2. 保留原编号和顺序，不为分卷重排原来的 §136/§137/§138，也不拆开合并记录。截至 §334，当前分卷为 100、98、100、30 条，封卷后不向旧卷补新批次。
3. 新批次追加到当前卷。达到 100，或追加完整合并记录会超过 100 时，创建下一卷 `history-05.md` 等；同步上一卷/下一卷导航、本目录当前卷链接、入口索引和交接摘要。
4. 每条新记录写清改动目的、真实完成内容、验证与限制、专项文档/结果清单和下一步；不把同一链路的内部步骤机械拆成多批。
5. 更新当卷容量、任务入口索引和收口账本状态后，执行工作流中的文档一致性检查；检查未通过时不得进入下一批业务实现。
