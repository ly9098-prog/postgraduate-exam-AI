# 八、异步处理器可靠性测试

对 processor 做并发、崩溃和恢复测试。

## 8.1 原子领取

创建一个 pending 任务，让两个 processor 同时尝试领取。

要求：

- 只有一个 processor 成功；
- PDF 或 DOCX 只生成一次；
- 只上传一个最终文件；
- 数据库状态一致；
- 不产生孤儿文件。

## 8.2 并发限制

验证：

- 单用户最多两个 pending/processing 的真实语义；
- 限制是否在并发请求下仍有效；
- 不同用户不会互相占用配额；
- completed、failed、expired 是否正确释放配额；
- retry 和 re-export 是否受合理限制；
- 错误提示对用户可读。

如果“最多两个”包含 pending 和 processing，应在代码和文档中保持一致。

## 8.3 超时

验证 600 秒任务超时机制：

- 超时后任务进入受控失败状态；
- 生成子进程、线程或任务真实停止；
- 不继续上传文件；
- 临时目录清理；
- Redis 锁释放；
- 数据库锁释放；
- 后续可以重试；
- 不产生 zombie 后台执行。

测试环境可通过较短的可配置超时模拟，不要实际等待 600 秒。

## 8.4 Zombie 恢复

验证：

- processor 在 processing 状态时崩溃；
- heartbeat 停止；
- 超过阈值后任务可恢复；
- 正常长任务持续 heartbeat 时不会被误判；
- 多个恢复器不会重复恢复；
- 恢复后不会使用损坏的临时文件；
- 原有孤儿文件可以清理。

## 8.5 故障注入

至少模拟：

- Redis 不可用；
- PostgreSQL 短暂断开；
- 文件系统无写权限；
- 磁盘空间不足或模拟写入失败；
- COS 上传失败；
- 文件上传成功后数据库提交失败；
- PDF 生成异常；
- DOCX 生成异常；
- 图片下载超时；
- processor 循环内部未捕获异常。

processor 主循环不能因单个任务异常永久退出。
