# 一、首先关闭剩余问题

## 1.1 修复 preview-count 权限缺失

当前已知问题：

> `POST /api/v1/exports/preview-count` 未检查导出总开关和用户白名单，未授权用户可能探测自己的错题数量。

此问题必须在全量开放前修复，不继续作为后续排期。

`preview-count` 必须执行与创建任务接口一致的基础权限检查：

1. 用户已登录；
2. `EXPORT_FEATURE_ENABLED=true`；
3. 当前用户位于白名单，或 `EXPORT_ALLOW_ALL_USERS=true`；
4. 请求范围属于当前用户；
5. selected IDs 属于当前用户错题本；
6. DOCX 是否启用不影响纯计数，除非请求中包含文件格式；
7. 功能未开放时返回结构化错误码；
8. 不向未授权用户返回题目数量；
9. 不通过错误信息泄露筛选结果是否存在；
10. 能力接口与 preview-count 的权限判断必须复用同一服务或函数。

禁止在多个端点分别复制不同版本的白名单判断。

建议抽取统一能力服务，例如：

- `ExportCapabilityService`
- `get_export_capability(user)`
- `ensure_export_creation_allowed(user)`
- `ensure_format_allowed(user, format)`

具体名称遵循现有项目风格。

增加测试：

- 总开关关闭时 preview-count 被拒绝；
- 白名单外用户被拒绝；
- allow-all 用户可以访问；
- 白名单用户可以访问；
- selected IDs 越权被拒绝；
- all 范围不会应用页面 filters；
- filtered 范围正确计数；
- 返回结构化错误码。
