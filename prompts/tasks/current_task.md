------

你现在需要优化一个功能模块：“代码题结构修复（AI 补全配置）”。

当前问题：
该功能对代码题中的结构错误（如断行、运算符拆分、缩进混乱）修复效果不稳定，甚至部分输入无变化。

------

# 🧠 任务模式：审计 → 规划 → 实现（必须严格执行）

你必须按照以下三个阶段输出，不允许跳步：

------

# 🧩 第一阶段：审计（Audit）

请先对当前问题进行结构审计，包括：

### 1. 输入问题类型分类

识别常见错误类型，例如：

- 运算符断裂（+ +、< =、* =）
- 代码断行错误（if / for / 参数被拆开）
- 缩进结构丢失
- 代码与题干混排
- 代码块缺失或错误

------

### 2. 当前系统失败原因分析

说明为什么现有“修复功能”无效，例如：

- 是否没有 token 级处理
- 是否没有结构识别
- 是否只是文本替换
- 是否没有代码块边界感知

------

### 3. 问题本质总结

用一句话总结核心问题，例如：
“当前系统是文本补全器，而不是结构恢复器”

------

# 🧭 第二阶段：规划（Plan）

基于审计结果，设计一个新的修复方案架构，必须包含：

------

## 1. 总体处理流程（必须分步骤）

例如：

1️⃣ 代码区域识别
2️⃣ token 断裂修复
3️⃣ 语法结构重建
4️⃣ 缩进/层级恢复
5️⃣ 输出标准化

------

## 2. 每一步的输入输出定义

例如：

- 输入：原始混乱文本
- 输出：结构化代码块

------

## 3. 关键规则设计（必须包含）

至少包括：

- 运算符合并规则（++, >=, *=）
- 换行合并规则
- 控制流结构识别规则（if/for/while）
- 代码块边界识别规则

------

## 4. 成功标准（必须量化）

例如：

- 代码可读性恢复
- 语法结构完整
- 不改变语义
- 无多余换行

------

### 3. 必须包含示例

### 4. 输出格式统一

- 保持题干不变
