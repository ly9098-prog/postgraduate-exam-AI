## 三、已确认的性能热点

当前代码中至少存在以下问题，请逐项核查并处理，而不是仅做表面调参：

1. `_startAnimations()` 在同一个动画循环中同时执行：
   - 多次跨线程 `setData` 更新 4 个数字/文本；
   - `_renderPieChart()`；
   - `_renderTrendBars()`。
   这会让逻辑层、视图层和两个 Canvas 同时争用主线程。

2. 饼图 `_renderPieChart()` 在动画最后约 10% 集中启用多项昂贵效果：
   - 多层侧面深度绘制；
   - `clip()`；
   - 多个线性/径向渐变；
   - 阴影、中心光、外圈高光、冰霜、Gloss、Specular 等叠加层。
   这正是最后几帧明显卡顿的主要原因之一。

3. `_startAnimations()` 的终帧存在重复绘制：当 `rawP >= 1` 时，节流分支先绘制一次 `progress=1`，随后结束分支又再次调用 `_renderPieChart(1)` 和 `_renderTrendBars(1)`。

4. 数据加载结束后一次性挂载概览、两个 Canvas、图例和最多 20 条历史记录；历史记录又全部带交错入场动画，同时数字和图表也在动画，形成动画风暴。

5. 当前页面加载阶段使用 Lottie Canvas，数据加载完成后马上销毁加载 Canvas、创建两个新 Canvas 并开始动画，低端机上可能增加瞬时资源竞争。

6. `onShow()` 每次都调用 `loadData()`，需要防止重复请求、并发加载、页面快速切换后的过期回调，以及返回页面时不必要的全屏 loading 和整页重播动画。

## 四、必须采用的性能重构原则

### 4.1 Canvas 不再做高成本逐帧全量重绘

首选方案：

- 数据和 Canvas 就绪后，分别把趋势图和最终高质量饼图静态绘制一次；
- 图表入场使用 WXSS 的 `opacity + transform`，例如轻微 `scale/translateY`，时长约 240–360ms；
- CSS 动画只作用于 Canvas 元素或其容器，不在每帧重建渐变、裁剪路径和多层扇区；
- 点击选中扇区时允许重绘一次，关闭详情时允许重绘一次；不要为选中态启动持续 Canvas 动画。

如果你判断必须保留扇区展开动画，则必须采用“两阶段渲染”：

- 动画阶段只画简化的顶面扇区，禁止侧面多层、阴影、clip、Gloss、Specular 等高成本效果；
- 动画结束后只进行一次最终高质量静态绘制；
- 严禁在最后 10% 逐帧叠加多个高成本效果；
- 严禁重复绘制终帧。

### 4.2 降低 `setData` 频率与体积

- 不要在 Canvas `requestAnimationFrame` 中持续调用 `setData`；
- 数字可以直接显示最终值，或最多用少量离散步进实现轻量动画；
- 若保留数字动画，必须与 Canvas 绘制解耦，更新次数要显著减少，并在页面隐藏/卸载时可取消；
- 只提交发生变化且视图真正需要的字段；
- 内部状态尽量保存在实例字段中，不要把纯内部字段放进 `data`，除非 WXML 需要。

### 4.3 优化加载与生命周期

- 首次进入可显示轻量骨架屏，建议在本页停用 Lottie，避免加载 Canvas 与图表 Canvas 连续切换；
- 骨架屏只使用轻量背景块和简单透明度动画，不使用 `filter`、`backdrop-filter` 或高开销模糊；
- 首次请求完成后先快速展示真实内容，再在合适时机初始化静态图表；
- 返回页面时优先保留旧数据并静默刷新，不要重新显示全屏 loading，不要重播整页全部动画；
- 为 `loadData()` 增加并发保护或请求版本号，确保快速进入/退出或连续触发时，旧请求不能覆盖新状态；
- `onHide()` 与 `onUnload()` 都要停止计时器、RAF 和未完成的页面动画状态；
- 初始化两个 Canvas 时尽量使用一次组合 selector query，避免两次独立查询；
- DPR 上限继续控制在 2，并根据设备能力或画布尺寸合理降级，禁止为了视觉效果使用超大 backbuffer。

### 4.4 减少列表动画竞争

- 历史记录不要让 20 项全部长时间交错入场；
- 最多只给前 4–6 项一个很短的渐入，或直接取消逐项动画；
- 总入场时长不要超过约 300ms；
- 兼容系统“减少动态效果”设置；
- 页面刷新时不要重复播放所有历史项动画。

## 五、立体饼图 UI 重构要求

请把当前“厚重冰晶圆饼”重构为“现代深色立体环形饼图（donut-style pie）”。它仍然属于饼图，但中心留白用于强化核心数据。

### 5.1 视觉方向

- 深色沉浸式统计卡片；
- 透视克制，椭圆压缩不要过扁，建议 `tilt` 约 0.66–0.74；
- 立体厚度明显但不过重，建议约图表直径的 7%–10%；
- 内圆半径建议为外圆半径的 48%–58%；
- 光源统一从左上方进入；
- 顶面使用轻微方向性明暗渐变；
- 侧面只比顶面暗一个层级，并有轻微纵向渐变；
- 只保留一个柔和落地阴影、一个薄高光边和必要的扇区分隔；
- 删除或显著收敛当前中心爆光、冰霜覆盖、外圈粗光、多个叠加 Gloss/Specular 等效果；
- 扇区之间留很小的视觉间隔或暗色分隔线，不能出现刺眼的白色粗描边；
- 相邻扇区颜色要有足够区分度，在深色背景下保持可读性；
- 不要使用夸张霓虹、廉价塑料感或过度拟物效果。

### 5.2 中心信息

环形中心显示：

- 小标题：`今日专注`
- 主数值：当天总学习时长，复用现有格式化逻辑
- 可选辅助信息：番茄总数

中心文字建议用 WXML 绝对定位叠在 Canvas 上方，而不是每次随 Canvas 重绘，以获得更清晰的字体和更低的绘制成本。

### 5.3 图例

重构图例，使其更像成熟产品的数据明细：

- 每项至少展示颜色点、科目名、时长、占比；
- 保持紧凑清晰，可采用两列或纵向列表；
- 长科目名需省略处理；
- 百分比与时长的层级清晰；
- 不要为了美化增加大量阴影或模糊。

### 5.4 交互

保留现有点击扇区查看详情的能力：

- 点击命中算法必须适配环形内半径；点击中心空洞不应选中扇区；
- 选中扇区只做轻微外移（约 4–8px）和亮度/描边变化；
- 选中态重绘一次即可，不要启动连续动画；
- 继续支持单扇区、极小扇区、7 个科目、0 数据等边界情况；
- 详情弹层、日期选择、历史记录及现有 API 行为不能被破坏。

## 六、建议的代码结构

请根据实际代码调整命名，但建议拆分为类似结构：

- `_prepareChartData()`：只计算一次比例、角度、颜色和命中区域；
- `_initCanvases()`：一次查询并初始化两个 Canvas；
- `_drawTrendChart()`：静态绘制趋势图；
- `_drawPieChart(options)`：静态绘制最终立体环形饼图；
- `_drawPieShadow()`、`_drawPieSides()`、`_drawPieTop()`：职责清晰，避免一个超长函数；
- `_scheduleChartPaint()`：在视图提交完成后安排一次绘制，防止重复调度；
- `_cancelPendingWork()`：统一取消 RAF、timer 和待执行绘制；
- `_getPieHitSubject(x, y)`：独立命中测试，适配内外半径和椭圆坐标。

不要为了形式机械拆函数；目标是降低重复计算、减少每帧分配、便于维护。

## 七、具体性能约束

修改后的实现应满足：

1. 页面首次显示真实内容时，不再同时启动两个 Canvas 的高成本逐帧动画。
2. 饼图加载动画最后几帧不再新增大量特效绘制。
3. 首次加载时最终高质量饼图原则上只完整绘制一次。
4. 不再出现终帧重复绘制。
5. Canvas RAF 回调中不得进行高频 `setData`。
6. 不得在每一帧重复计算扇区总时长、角度、颜色解析和静态几何。
7. 不得在每一帧创建大量可缓存的渐变或阴影对象。
8. 图表入场优先使用只改变 `transform` 和 `opacity` 的 WXSS 动画。
9. 返回页面静默刷新时，不得闪回全屏 loading。
10. 不新增第三方依赖，不改变服务端接口。
