# 番茄钟 408 四科均分计时

**状态：实现已完成；微信开发者工具编译、模拟器与真机验证待执行。** 本任务为一个番茄钟增加“计算机综合（四科均分）”归属方式。用户只启动一次计时，系统把实际专注时长按四等分记入数据结构、计算机组成原理、操作系统、计算机网络。保留现有单科计时方式。

## 一、产品规则

- 选择现有 408 父级学科作为综合计时入口；界面明确显示“计算机综合 · 四科均分”及“每科 25%”，不把它展示成普通单科。
- 用户选择综合入口后只启动一个番茄钟。不要求逐科轮换、计时中切换学科或重复启动多个番茄钟。
- 四科按 `2500` 基点各分配 25%，总权重为 `10000`。只对本次计时开始时解析到的四个有效 408 叶子科目分配。
- 按服务端确认的实际专注秒数分配，暂停区间不计入。提前结束或中断时按已确认的实际专注时间分配，不按预设时长分配。
- 时间分配按整数秒计算，采用固定、可复现的余数规则，保证四科分配之和与原专注时长完全相等。
- 综合计时在番茄钟总次数中只计一次。学科明细中的次数定义为“参与专注次数”：同一综合番茄可分别计入四科的参与次数，因此学科次数不可相加推导总番茄数；界面文案必须表达这一点。
- 单科计时保持现有行为。历史记录不重新分摊，继续按原 `subject_id` 统计。

## 二、学科选择界面

- 将选择区改为三列网格。当前八个单科选项加一个“四科均分”选项时正好组成 3×3，避免四列布局最后一行只剩一个选项；较宽的单元格也给科目名称和触控区域留出空间。
- 组合选项作为单独的选择范围加入网格，排在首位；其后按现有顺序显示四个 408 叶子和其他单科。只从实际可用的学科树构造选项，不创建占位项填格。后续选项数变化时自然换行，保持左对齐。
- 所有学科选项使用同一套线性 SVG 图标，不用 emoji 或学科首字代替图标。图标按稳定科目编码映射：`data_structure` → `workflow`，`computer_organization` → `cpu`，`operating_system` → `panels-top-left`，`computer_network` → `network`，`advanced_math` / `math2-calculus` → `square-function`，`linear_algebra` / `math2-linalg` → `grid-2x2`，`english` → `languages`，`politics` / `pol` → `landmark`。
- 使用从 Lucide 官方图标库获取的 SVG，并随小程序本地打包，不在运行时请求远程图标；沿用已有 `miniprogram/assets/icons/diagnosis-subject/` 中的四个 408 科目图标，新增图标保持相同线条风格，并在资源目录记录来源和许可证。
- 组合项保持与网格一致的单元格尺寸和整体视觉语言，以四个 408 科目线性图标组成紧凑的 2×2 组合标记；不以“数、组、操、网”等首字充当图标。标题使用 408 父级的真实名称，副标题显示“四科各 25%”。它不使用横向长卡片，也不伪装成普通单科。
- 组合项和单科选项互斥。选中组合项时只高亮组合项；不同时高亮四个子科目，避免被理解成四个独立计时。
- 选择组合项后沿用当前“开始专注”流程，不增加确认弹窗或中间步骤。准备页、计时页和恢复中的会话均显示“计算机综合（四科均分）”。
- 子科目名称和 ID 从当前学科树按 canonical `subject_code` 解析，不硬编码数据库 ID。四个 408 核心叶子不齐、不可用或不满足校验时，禁用综合项并说明科目配置不可用；不得用其他科目补位或静默改为不等分。
- 保持浅色/深色主题下选中、按下、禁用状态清楚可辨；小屏检查科目名换行/截断和触控面积，避免相邻选项误触。

## 三、数据与 API

- `/api/v1/pomodoro/start` 支持明确的分配模式，例如 `equal_408_core_v1`。单科请求保持兼容；综合请求使用现有 408 父级 ID，并由服务端解析有效的四个核心叶子科目及其各 25% 权重。
- 服务端校验综合模式只对应已启用的 408 父级及四个 canonical 核心叶子：`data_structure`、`computer_organization`、`operating_system`、`computer_network`。拒绝父级不匹配、叶子缺失或失效、重复叶子、非叶子科目和权重总和不为 10000 的请求。
- 新增按番茄会话保存学科分配的持久化结构，至少记录 `session_id`、叶子 `subject_id`、权重基点及稳定的科目代码/名称快照。一个会话可关联多个学科；同一会话与学科唯一，权重为正数。
- 会话主记录仍只表示一个真实番茄钟。综合会话的主 `subject_id` 保留父级，分配明细保存四个叶子；不得复制成四条番茄会话。
- 新建单科会话也写一条 10000 基点分配明细。旧记录没有分配明细时，统计层按其原 `subject_id` 解释为单科 100% 分配，避免回填或改写历史数据。
- 会话和分配明细在同一事务中创建。幂等启动重试返回第一次创建的分配快照，不因重试时学科目录变化而重新计算。
- `/start`、`/active`、恢复、完成、中断和历史记录响应都保留综合模式及分配明细，使前端重启、断网重试和跨端恢复后仍显示同一归属。
- 统计使用已保存的权重，对每个统计日拆分后的有效专注秒数分别分配，避免跨日、暂停和中断场景出现时长丢失或重复。父级和子级的汇总不得重复计入总体时长。

## 四、统计与兼容边界

- 总专注时长和总番茄次数仍以真实会话计一次；学科分布按分配明细累计时长。
- 学科参与次数允许同一综合会话出现在四个科目的参与数中，需在 API 和统计页明确命名为“参与专注次数”。所有全局番茄次数仍只计真实会话数。
- 更新所有 Pomodoro 学科汇总与消费方，包括日/周/月/自定义区间统计、趋势、分布、统计详情、历史记录及学习计划按学科读取的计时数据。先检索所有 `PomodoroSession.subject_id` 消费点，避免图表与学习计划口径不一致。
- 保留已有单活动计时、暂停区间、离线待同步、启动幂等、结束重试和服务端时长校准语义。
- 数据库使用新增 Alembic 迁移；不删除或重建既有会话表，不改写历史会话。数据库权威文档与 Pomodoro API 文档同步更新。
- 本任务不实现自定义比例、计时中切换、轮换计划、多活动计时或四条重复会话。

## 五、实施与验收

- 后端单元测试覆盖 25% 权重校验、整数秒余数分配、分配总和守恒、父子学科范围校验和不可用科目处理。
- API 测试覆盖单科兼容、综合启动、幂等重试、活动会话读取、暂停/恢复、完成、中断及旧会话响应。
- 统计回归覆盖跨统计日、暂停区间、提前中断、自由计时、历史无分配明细的单科记录；全局时长和总番茄数不得重复，四科分配时长之和必须等于有效专注时长。
- 数据库迁移验证 SQLite 与 PostgreSQL，升级前后既有 Pomodoro 行数、时长、状态和单科归属不变。
- 小程序回归验证三列网格当前 3×3 排列、组合项与单科互斥、选项数变化时不生成占位项、线性 SVG 图标与选中状态正确、无 emoji/首字图标、选择后计时标题正确、活动会话恢复正确、浅色/深色模式和窄屏触控可用。
- 按仓库规则运行受影响后端 pytest、`compileall`、Ruff、相关小程序 Node 回归脚本，并在微信开发者工具编译和模拟器检查。明确区分模拟器与真机验证。
- 完成代码和迁移检查后，先报告变更与验证结果；生产迁移或部署不属于本任务，除非用户另行提出。
